Séquence — Confirmation et clôture d'une alerte

§ 2.4.3 — sequenceDiagram
Deux étapes successives : Confirmer (met confirmee: true → carte orange) puis Mission terminée (met traitee: true → carte verte). Chaque mise à jour Firestore déclenche automatiquement le StreamSnapshot qui reconstruit l'UI.

{ confirmee: true } DB-->>AS: ✅ Succès Note over DB,AS: Le StreamSnapshot déclenche
automatiquement une mise à jour AS->>AS: Reçoit snapshot mis à jour
notifyListeners() AS-->>UI: Reconstruit la carte alerte UI-->>U: Statut → "Mission confirmée" 🟠 end Note over U: Le sauveteur se rend
sur le lieu de l'incident rect rgb(232, 245, 233) Note over U,DB: ── Étape 2 : Clôture après intervention ── U->>UI: Clique "Mission terminée" UI->>AS: traiterAlerte(alerte.id) AS->>DB: UPDATE alertes/{id}

notifyListeners() AS-->>UI: Reconstruit la carte alerte UI-->>U: Statut → "Mission accomplie" 🟢 end Note over U: L'alerte est archivée
et disparaît des alertes actives

Structure des collections Firestore

§ 3.3.1 — flowchart
Trois collections NoSQL : users (chargée une fois au démarrage), alertes (stream temps réel écrit par le RPi), historique (stream temps réel écrit par les sauveteurs). Les flux bidirectionnels garantissent la synchronisation instantanée entre tous les appareils.
